# Task and API contract

Both the web page and the MCP tools use this API. Only the API opens SQLite.

| Operation | HTTP | MCP tool |
| --- | --- | --- |
| List/filter | `GET /tasks` | `list_tasks(completed?, course?, due_before?)` |
| Create | `POST /tasks` | `create_task(title, course?, due_date?)` |
| Edit/reopen | `PATCH /tasks/{id}` | `update_task(task_id, changes)` |
| Complete | `POST /tasks/{id}/complete` | `complete_task(task_id)` |

Lists return JSON arrays. Successful writes return the saved task object with
its ID. Creation returns HTTP 201; missing IDs return 404; invalid input returns
422; unavailable SQLite storage returns 503.

```json
{
  "id": 1,
  "title": "Finish the EAI assignment",
  "course": "EAI",
  "due_date": "2026-11-20",
  "completed": false
}
```

## Field rules

- `id`: stable integer generated by SQLite.
- `title`: required trimmed text, 1-200 characters.
- `course`: optional trimmed label, 1-80 characters, or null. Filters match exactly and case-sensitively.
- `due_date`: optional real calendar date in exactly `YYYY-MM-DD`, or null.
- `completed`: false on creation; a boolean when edited.

Updates change supplied fields only. Null clears `course` or `due_date`; title
and completed cannot be null. An empty update is a no-op for an existing ID.
Unknown fields are rejected. An example MCP update is:

```json
{"task_id": 1, "changes": {"due_date": "2026-11-22", "course": null, "completed": false}}
```

Filters combine with AND. `due_before` includes that date and excludes undated
tasks. Results use newest ID first. Completing twice has the same final state
as completing once. The page labels a task overdue only when it is incomplete
and dated before today in Asia/Beirut; undated tasks are never overdue.

There is no delete operation. Completed tasks remain available as history.
Use explicit IDs, and clarify ambiguous titles before changing records.

## Errors and configuration

MCP adapter failures are tool errors, not success-shaped messages. Writes are
not automatically retried: after a lost response, refresh/list before creating
again because the original write may already have saved.

| Variable | Default | Purpose |
| --- | --- | --- |
| `UNIPLAN_DB_PATH` | Root `tasks.db` | Database override; relative paths resolve against `database.py`'s directory. |
| `APP_BASE_URL` | `http://127.0.0.1:8000` | MCP adapter's API address; match it to the running API port. |

The database and static paths are independent of the launch directory.
Back up `tasks.db` while the application is stopped.
